# 事件库写作模板（_TEMPLATE）

> 本文件夹是**世界库的写作模板**。新增一个世界时，复制整个 `_TEMPLATE` 文件夹，
> 重命名为世界 id（例：`cyberpunk` / `three_kingdoms`），再按下文替换内容。
> 主索引见仓库根目录 `FILE_INDEX.md`，协作规则见 `PROJECT_SYNC.md`。

---

## 一、文件夹结构

```
<worldId>/
├── world.ts        世界元数据：简介 / 开场独白 / 背景包 / 专属标签 / 死因文案
├── childhood.ts    幼年  0-6
├── teen.ts         少年  7-15
├── youth.ts        青年  16-25
├── prime.ts        壮年  26-40
├── middle.ts       中年  41-60
├── elder.ts        老年  61+
└── index.ts        聚合导出（必须导出 WorldPack，引擎只认这个）
```

## 二、写作六步

1. 写 `world.ts`：定世界观基调、6~8 个开局背景包、专属标签池、死亡原因文案。
2. 按年龄段写事件文件，**每个阶段 ≥ 18 条**，其中抉择事件 ≥ 60%。
3. 每条抉择都必须带 `check`（属性检定），写清 `success` / `fail` 两种走向。
4. 数值自检：单条事件属性变化建议 ±1~3，重大剧情节点最多 ±6；属性 0~20 封顶。
5. 跑一遍自检清单（见文末）。
6. 更新 `FILE_INDEX.md` 与 `PROJECT_SYNC.md`。

---

## 三、字段规范

| 字段 | 必填 | 规范 |
|---|---|---|
| `id` | ✅ | `世界前缀_阶段_三位序号`，例 `cb_teen_007`；全局唯一，禁止复用 |
| `stage` | ✅ | 六阶段之一，必须与所在文件一致 |
| `title` | 建议 | 4~8 字，用于总结图时间线 |
| `text` | ✅ | 正文 40~80 字，可用 `\n` 换行；不要写心理活动总结，要写具体画面 |
| `weight` | ❌ | 默认 1；想让它更常出现就调到 2~3 |
| `once` | ❌ | 默认 true（一生一次）；需要反复出现的事件显式写 `once: false` |
| `require` | ❌ | 触发条件：年龄 / 属性区间 / 标签 / 概率，可用 `all` `any` 组合 |
| `choices` | ❌ | 有 = 抉择事件；无 = 自动推演事件（此时必须写 `effects`） |
| `effects` | ❌ | 自动事件的结果；抉择事件的结果写在各分支里 |
| `tags` | ❌ | 事件检索标签，如 `['义体','街头']` |

## 四、属性写法（重要）

事件库**只允许使用语义属性键**，不要出现「智力」「洞见」这类具体属性名：

| 语义键 | 含义 | 经典五维中的落点 | 心之禀赋中的落点 |
|---|---|---|---|
| `perception` | 感知 / 洞察 | 智力 | 洞见 |
| `will` | 意志 / 持守 | 体质 0.5 + 快乐 0.5 | 持守 |
| `empathy` | 共情 / 通感 | 快乐 0.7 + 颜值 0.3 | 通感 |
| `ingenuity` | 应变 / 机变 | 智力 | 机变 |
| `reverie` | 灵感 / 遐思 | 快乐 | 遐思 |
| `vitality` | 行动 / 行力 | 体质 | 行力 |
| `charm` | 外在魅力 | 颜值 | 背景词条评分 |
| `wealth` | 家资 | 家境 | 背景词条评分 |
| `health` | 身体 | 体质 | 行力 0.6 + 持守 0.4 |
| `mood` | 心境 | 快乐 | 持守 0.5 + 遐思 0.5 |

## 五、检定写法

```ts
check: { attr: 'empathy', dc: DC.normal }
```

- 掷 `1d20 + floor(属性/2) ≥ DC` 即成功；**骰面 20 大成功，骰面 1 大失败**。
- 难度档位：`DC.easy` 10 / `DC.normal` 13 / `DC.hard` 16 / `DC.extreme` 19。
- **作者只写 `success` 与 `fail` 两种结果，大成功 / 大失败由引擎自动强化**（效果加倍 + 附加标签），无需另写。
- 选项选择哪条路，看这条路**最吃哪种能力**：识破谎言→`perception`，扛住痛苦→`will`，说服人→`empathy`，
  临场想办法→`ingenuity`，赌一把灵感→`reverie`，硬闯/体力活→`vitality`。

## 六、文风要求

- 具体优先于抽象：写「雨水从义体颈口的缝里渗进去」，不写「你感到很悲伤」。
- 留白：结尾留一个未说破的画面，把判断权交给玩家。
- 世界质感统一：每个世界有自己的物（赛博朋克的酸雨 / 义体 / 信用点；三国的竹简 / 军功 / 粮）。
- 数值与文本对齐：文本写「差点被抓住」，就不要给 `+5` 的收益。

## 七、禁止事项

1. 禁止在事件里写具体属性名（智力 / 洞见 / 颜值…），只能用语义键。
2. 禁止 `effects` 全为空——每次选择都必须改变点什么（正文里的「不让属性不变」原则）。
3. 禁止 `next` 指向不存在的事件 id。
4. 禁止死亡事件不给原因（`death` 必须填死因文案）。
5. 禁止单条事件数值超过 ±6。

## 八、自检清单

- [ ] id 全局唯一，且与文件名 / 阶段一致
- [ ] 每条抉择都有 `check`，且 `success` 与 `fail` 都写了
- [ ] `require` 中的年龄区间与所在阶段匹配
- [ ] `next` 指向的 id 真实存在
- [ ] 属性增减在 ±1~3 区间，重大节点 ≤ ±6
- [ ] 死亡事件填了 `death` 文案，且触发条件合理（不是随机暴毙）
- [ ] 事件文本 40~80 字，无错别字，世界观用词统一
- [ ] 阶段事件数 ≥ 18
