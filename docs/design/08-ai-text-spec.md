# 08 · 剧情文本生成规范（给 AI 的规则）

> 状态：2026-09-24 新增
> 用途：把**整份文档**作为规则（系统提示）发给任何 AI，让它产出本引擎可直接加载的事件 JSON。
> 适用范围：官方事件库扩写、AI 线路生成、玩家上传文本转分支（附录 A）。
> 关联：[01 剧情引擎](./01-heart6-spec.md) · [02 人物构建层](./02-character-layer.md) · [04 人生模型](./04-life-model.md) · [06 AI 线路](./06-ai-route.md)

---

## 1. 你在写什么

你在为「人生重开式叙事跑团」写**人生事件**。一个事件 = 一段第二人称的处境描写 + 若干选项（或无选项的自动事件）。玩家每年遇到一个事件，做出选择，掷骰结案，直到死亡。

引擎不认识抒情，只认识字段。**所有玩法影响必须写在结构化字段里，正文只负责氛围与处境。**

## 2. 硬性格式

### 2.1 事件 JSON 模板

```json
{
  "id": "cb_teen_031",
  "stage": "teen",
  "title": "雨水税上门",
  "text": "收水队的电棍在楼道里敲出回声。母亲把你按进柜子，自己迎了上去。\n门缝里，你看见她把整月的工牌押在桌上。",
  "weight": 1,
  "once": true,
  "require": { "age": [7, 15], "tags": ["欠雨水税"] },
  "choices": [
    {
      "label": "冲出去挡在母亲前面",
      "major": true,
      "check": { "attr": "will", "dc": 12 },
      "success": { "text": "对方愣了一下，骂骂咧咧地退了。", "effects": { "attr": { "will": 1 }, "psyche": { "trust": 1 } } },
      "fail": { "text": "你被一电棍撂倒，母亲替你挨了双倍。", "effects": { "attr": { "health": -2, "mood": -2 }, "psyche": { "suppression": 2 } } },
      "critSuccess": { "text": "收水队的人记住了你的脸，再没来过这条街。", "effects": { "attr": { "will": 2 }, "tags": ["街头名声"] } },
      "critFail": { "text": "电棍落在你太阳穴上，世界黑了三秒，再亮起时救护车的灯在闪。", "effects": { "attr": { "health": -4 }, "psyche": { "suppression": 3 } } }
    },
    {
      "label": "从后窗溜走，去找锈牙帮的人",
      "check": { "attr": "ingenuity", "dc": 10 },
      "success": { "text": "你穿过三条巷子，把话带到了。", "effects": { "attr": { "ingenuity": 1 }, "tags": ["锈牙帮"] } },
      "fail": { "text": "你在铁皮墙头摔了下来，尾椎疼了一个月。", "effects": { "attr": { "health": -1, "mood": -1 } } }
    },
    {
      "label": "把脸埋进膝盖，等它结束",
      "effects": { "attr": { "mood": -1 }, "psyche": { "suppression": 1 } }
    }
  ]
}
```

### 2.2 字段表（LifeEvent）

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✔ | `世界前缀_阶段_三位序号`，如 `cb_youth_032`。全局唯一，**先查重再加** |
| `stage` | ✔ | `childhood`(0-6) / `teen`(7-15) / `youth`(16-25) / `prime`(26-40) / `middle`(41-60) / `elder`(61-120) |
| `title` | 建议 | 一行短题，总结图时间线会展示 |
| `text` | ✔ | 正文，见第 3 节风格规则；`\n` 可换行 |
| `weight` | – | 抽取权重，默认 1。普通事件 1，日常凑数 0.5，人生转折 2~4 |
| `once` | – | 默认 true（一生一次）。日常型可 false |
| `require` | – | 入池条件，见 2.4 |
| `choices` | – | 有 = 玩家抉择事件；无 = 自动事件（配顶层 `effects`） |
| `effects` | 自动事件必填 | 自动事件的固定结算 |
| `tags` | – | 检索标签（给事件本身贴的标记，供后续事件 require.tags 引用） |

**自动事件**不要写 `choices`，把结算写在顶层 `effects`，正文写清「发生了什么、结果如何」。

### 2.3 选项（Choice）字段表

| 字段 | 说明 |
|---|---|
| `label` | 选项文案：动作短句，不超过 18 字，能一眼看出「要做什么」 |
| `require` | 选项可见条件（属性/标签/能力）。**至少留一个无 require 的选项**，任何情况下玩家必须有得选 |
| `check` | 检定 `{ "attr": 语义键, "dc": 难度 }`。省略 = 必定成功的叙事型选项，需配顶层 `effects` |
| `success` / `fail` | 检定两分支，结构为 `{ "text": 旁白, "effects": {...}, "next": "事件id" }` |
| `critSuccess` / `critFail` | 大成功 / 大失败写死分支，见第 5 节 |
| `major` | true = 关键抉择，界面高亮。**一局 5~8 个为宜**，别滥用 |
| `next` | 连锁到指定事件 id（做因果链用） |

### 2.4 条件（Condition）写法

```json
{ "age": [16, 25], "tags": ["锈牙帮"], "notTags": ["神经污染"], "chance": 0.6 }
{ "attr": { "perception": [7, 99] } }
{ "caps": ["wheelchair"], "notCaps": ["blind"] }
{ "any": [ { "tags": ["小生意"] }, { "tags": ["街头名声"] } ] }
```

- `tags` 全部持有 / `notTags` 一个都不能有；`caps` 同理（能力标签）。
- `chance` 是额外概率，放在最外层做「偶发事件」。
- 语义键只有 10 个：`perception`(感知) `will`(意志) `empathy`(共情) `ingenuity`(应变) `reverie`(灵感) `vitality`(行力) `charm`(魅力) `wealth`(家资) `health`(身体) `mood`(心境)。

## 3. 文本风格（这条最容易写砸）

1. **第二人称「你」**。全篇只出现一个视角，不写「玩家」。
2. **40~80 字**（自动事件可到 120）。多一个字都从形容词开始删。
3. **写处境，不写评价**。不写「你感到绝望」，写「天花板的水痕又多了一圈」。
4. **赛博贫民窟质感**：雨水税、电棍、义体、接入仓、合成面馆、楼道声控灯。少用「企业""反乌托邦""科技"这类词——这个世界的人不这么说话。
5. **正文绝不出现数值**。不写「体质+2」「检定成功」，数值属于 effects。
6. **结局旁白不撒安慰**。death 事件的 text 写事实，不写「至少你努力过」。
7. 每个事件要**有因果出口**：text 里埋的细节（工牌、巷子、锈牙帮）应能被选项接住。

## 4. 数值与平衡

### 4.1 属性增减量级（attr，语义键）

| 情形 | 量级 |
|---|---|
| 日常小事的得与失 | ±1 |
| 真正的锻炼 / 真正的创伤 | ±2 |
| 人生转折（失明、入帮、发财） | ±3，且必须 `major` 或带 tags 变化 |
| 单事件合计 | 绝对值 ≤ 6 |

### 4.2 其他资源

- `money`（信用点）：幼年 0 量级；少年 ±20；青年 ±100；壮年起 ±500。底层没余钱，别乱发。
- `psyche`（心理）：`suppression`(压抑) 只在受挫/忍气吞声时 +1~3；`trust`/`selfWorth`/`resilience` 变动 ±1~2。病理触发由引擎按压抑度结算，**AI 不直接写病理特质名**。
- `gainTraits` / `loseTraits`：只在人生转折时用，写特质 id（如 `cyber_chrome_arm`），并同时在 text 里给出体感描写。
- `tags`：优先复用世界已有标签——赛博朋克高频表：`锈牙帮` `小生意` `义体化` `神经污染` `街头名声` `欠雨水税` `企业身份` `拿着根密钥`。新标签用中文短语，先查重。
- `death`：**只在事件的 fail/critFail 分支或自动事件顶层**出现，值是死因短语（如「收水队的电棍」「霓虹雨夜的失足」），引擎会拿它查世界死因池渲染文案。普通事件的失败分支不要轻易写 death——底层的一生应该死于积累（属性耗尽）或少数几个明确抉择。

### 4.3 检定难度（dc）

| dc | 含义 | 属性 10 时成功率 |
|---|---|---|
| 8 | 顺手的事 | ~85% |
| 10 | 有点悬 | ~75% |
| 12 | 真有难度 | ~65% |
| 14 | 赌一把 | ~50% |
| 16+ | 玩命 | ~35%↓ |

检定公式：1d20 + floor(属性/2) ≥ dc。骰面 20 大成功、1 大失败（引擎自动放大结算，见 §5）。事件库常见错误是全员 dc12——**难度要有分布，10~12 为主，14+ 稀缺**。

> **⚠ 2026-10-08 修订（待确认）**：此表的 dc 取值与 `engine/schema.ts` 的 `DC` 常量（`easy 10 / normal 13 / hard 16 / extreme 19`）以及 01 文档**三方不一致**，
> 且"属性 10 时成功率"的假设与实测不符（实测检定属性中位为 16，不是 10）。
> **新规则：dc 一律从 `engine/schema.ts` 的 `DC` 常量取值，不要在事件里写数字。** 完整的新难度表与实测成功率见 [09 文档](./09-fatality-and-consequence.md) 待校准项。

### 4.4 致死档位（2026-10-08 新增，待确认）

**死亡不是一种，是五档。写事件前先判断这一次属于哪一档。**

| 档 | 何时用 | 怎么写 |
|---|---|---|
| 寿终 / 衰竭 | 不需要写 | 引擎按属性与年龄自动判定，文案走世界 `deathCauses` 分池 |
| **抉择致死** | 玩家主动把命押上桌 | `Choice.major` + `critFail.effects.death` |
| **事故致死** | 坠落 / 机器 / 火灾 / 中毒 / 高危接入 | `Choice.hazard` 声明危险等级 + `critFail.effects.death` |

**危险等级表（`hazard`）**：

| 等级 | 典型情境 | 普通失败（`fail`） | 大失败（`critFail`） |
|---|---|---|---|
| `none` | 日常交涉、读书、买卖 | 仅属性/心理损失 | 数值 ×0.5 强化，**不致死** |
| `low` | 打架挨揍、熬夜硬扛 | −1~−3 属性 | ×0.5 强化 + 永久标签 |
| `mid` | 械斗、黑诊所手术、高危义体接入 | −3~−5 属性 + 永久标签 | 致死 **8%** 或永久残疾 |
| `high` | 从高处摔下、被车撞、重度感染 | −4~−6 属性 + 永久标签 + 1 条伤势 | 致死 **15%** |
| `lethal` | 卷入重工机器、爆炸、致命剂量 | 致死 **10%**（须写 `failLethal: 0.1`）+ 重伤 | 致死 **35%** |

**三条硬规则**：

1. **大失败致死率上限 35%** —— 不许写"大失败必死"；
2. **`failLethal` 只允许出现在 `hazard: 'lethal'` 的选项上**，且 ≤ `0.10`，其他等级写了直接打回；
3. **`hazard` 不是 `none` 的选项，正文必须给出危险信号**（"锈蚀的护栏""手不要伸过那条黄线"）——禁止突然致死。

**任何致死选项都必须在同一条事件里留至少一条不通向死亡的安全路径。**

### 4.5 失败的代价（2026-10-08 新增，待确认）

**`fail` 不等于"什么都没发生"。** 实测：现在 314 个失败分支里，行力在 3 步内回到失败前水平的占 **90%**——失败被后续事件冲掉了，玩家体感不到任何代价。

失败必须留下**三档代价**，按 `hazard` 等级有最低配额：

| 档 | 载体 | 说明 |
|---|---|---|
| 一档 | **伤势 `debuff`** | 持续 N 年每年扣属性，需要花钱/休养才能好；`permanent: true` 为终身 |
| 二档 | **永久标签 `tags`** | 长出因果支线（"右肩抬不起来"→ 后续事件可以 `require` 它） |
| 三档 | **残疾 / 病理 `gainTraits` / `gainCaps`** | 小概率，`mid` 以上、`critFail` 为主 |

最低配额：`none`/`low` 可选；`mid` 建议一档 + 必给二档；`high` 与 `lethal` **一档与二档必有**。

**唯一合法的"失败有收获"情形**：失败给的是**精神层面的成长**（`mood` / `empathy` / `selfWorth`），且**同时**有一档或二档代价。失败给的净收益 ≥ +2、或给了关键标签 → 审查打回。

### 4.6 「成功但有代价」`Outcome.cost`（2026-10-08 新增，待确认）

人生选择的本质是**取舍**，不是成败。当一次成功必然伴随失去时，**不要把代价写进正文就算了**——用 `cost` 让它真正结算：

```jsonc
"success": {
  "text": "你签了。电梯上行的时候，你没有回头看那条巷子。",
  "effects": { "attr": { "wealth": 3 }, "money": 20000, "tags": ["云台职员"] },
  "cost": {
    "attr": { "mood": -3 },
    "psyche": { "suppression": 2 },
    "dropTags": ["和余柚一起"],
    "debuff": [{ "id": "debuff_guilt", "years": 5, "label": "没说出口的话", "perYear": { "mood": -0.2 } }]
  },
  "costUnless": "critSuccess"   // 大成功 = 你两边都保住了
}
```

给 AI 的三条规则：

1. **每个 `major` 抉择都应该考虑要不要写 `cost`** —— 重大决定几乎总有代价；日常小事不必；
2. **`cost` 不参与大成功/大失败的数值缩放**（它与 `tags` / `death` 同类，是作者写死的因果）；
3. **`cost` 与 `effects` 要形成张力**：收益在一条线上，代价要在**另一条线**上（拿到钱但丢了关系、救下人但伤了身体），不要"加了 3 点又扣 3 点"这种相互抵消的写法。

> 完整语义（结算顺序、`costUnless` 规则、与 09 文档三档代价的分工）见 [10 文档](./10-outcome-and-attribute-rebalance.md) 第 2 节。

```jsonc
// fail 分支的正确形态
"fail": {
  "text": "钢缆在你手里打了滑。你摔在第三层的脚手架上，肋骨断了三根。",
  "effects": {
    "attr": { "health": -5, "vitality": -2 },
    "tags": ["摔断过骨头"],
    "debuff": [{ "id": "debuff_broken_ribs", "years": 3, "label": "肋骨未愈",
                 "perYear": { "vitality": -0.3 }, "costPerYear": 200, "cure": "rest" }]
  }
}
```

> 完整规范（五档死亡分类、`hazard` 全表、`Debuff` 类型定义、困境机制、现有数据的回头改清单）见
> **[09 致死档位与失败代价](./09-fatality-and-consequence.md)**。本节只保留给 AI 的写作要点。

### 4.4 寿命保护（重要）

本世界底层短寿：20 岁起身体/行力自然流失，普通人生约止于 40 岁。所以：
- **别在事件里滥发 vitality/health 正增益**——它们救不了衰减，只会制造虚假希望；给活力要走 `tags`（帮派、生意、义体保养线）。
- 40 岁后的事件（middle/elder）默认玩家已立住了什么，写法上给「守成与代价」，不是新开战场。
- elder 事件是顶层玩家的专属回报，写珍稀感：雨停、旧人、六点的面摊。

### 4.5 大成功 / 大失败（critSuccess / critFail）

- 引擎默认行为：没写 crit 分支时，大成功把数值 ×1.5、大失败 ×0.5。**写死分支优先于自动放大**。
- **关键抉择（major）建议写 crit 分支**：大成功可以直接改变人生走向（拿到稀缺 tags、避免本该到来的死亡），大失败可以 `death` 一骰定生死——这是「重点选项的大成功大失败能直接改变人生结局」的落地方式。
- 普通选项不要写 crit 分支，让引擎自动放大即可。

## 5. 残疾与能力门槛（caps）

能力标签（`caps`）：`blind`(失明) `deaf`(失聪) `wheelchair`(轮椅) 及后续扩展。来源是事件/特质的 `gainCaps`，一旦获得伴随一生。

写带能力门槛的内容时遵守三条：
1. **做加法不做减法**：给残疾人角色**追加**专属选项（`require: { "caps": ["blind"] }`，如靠听觉辨位、读唇、钩竿取物），**永远不要**把普通选项改成「残疾人不能选」。
2. 专属选项的正负结局都要成立，不写「因为残疾所以注定失败」。
3. 不用怜悯视角。盲人认得六点的面摊，不是「坚强的勇者」。

---

## 6. 内容安全

- 残疾 / 病理 / 成瘾在文本里只描述**处境与后果**（台阶、药瓶、手抖），不做感官化的痛苦描写，不做医疗指导。
- 未成年阶段（childhood/teen）不出现性、毒品细节、血腥特写。
- 事件的残忍度靠「失去什么」表达，不靠画面。

---

## 7. 交付前校验清单

- [ ] id 前缀、阶段、三位序号正确且全局唯一
- [ ] `stage` 年龄窗与 `require.age` 一致
- [ ] 每个抉择事件**至少一个无 require 选项**（玩家永不被堵死）
- [ ] 带 `check` 的选项必有 `success` + `fail`；无检定选项必有 `effects`
- [ ] 正文没有数值、没有系统词、字数达标
- [ ] effects 量级 ≤ §4 上限；单事件 attr 合计 ≤ 6
- [ ] tags 先查重；death 只出现在该出现的位置
- [ ] JSON 可被 `JSON.parse` 解析、无注释、无尾逗号
- [ ] **（2026-10-08 新增）危险情境已按 §4.4 判定并声明 `hazard`，正文给出了危险信号**
- [ ] **（新增）致死选项：`failLethal` 仅出现在 `hazard: 'lethal'`，且 ≤ 0.10；`critFail` 致死率 ≤ 35%**
- [ ] **（新增）同事件内至少存在一条不通向 `death` 的安全路径**
- [ ] **（新增）每个 `fail` 分支按 §4.5 配额给出了伤势 `debuff` / 永久标签**
- [ ] **（新增）没有"失败比成功划算"的分支（净收益 ≥ +2 或给关键标签）**
- [ ] **（2026-10-08 新增）重大抉择（`major`）若"得有所失"，已用 `cost` 显式写出，且代价与收益不在同一条线上**

## 8. 产出方式

- 官方扩写：每次交付一个阶段（如 teen 10 条），输出**纯 JSON 数组**，外面包一层 `/* stage: teen */` 注释即可，别带多余说明。
- 拿不准的词（世界观专名、标签）宁可用高频表里的，不要自造。

## 附录 A · 玩家上传文本 → 自动生成分支（规划，P1/P2）

流程设计（供后续实现参照，AI 侧约定先定下来）：

1. **输入**：玩家粘贴的一段人生故事文本（100~2000 字），声明期望年龄段。
2. **第一步（中间稿）**：AI 把自由文本压缩成**事件卡**——`{ 标题, 正文(40~80字), 选项 2~3 个(各带建议检定), 提取的 tags }`。中间稿给玩家看，不进引擎。
3. **第二步（编辑器）**：玩家在轻量编辑器里改正文措辞、调数值、删选项。编辑器只做四件事：改字、开关选项、拖动数值、预览检定概率。
4. **第三步（正式化）**：确认后 AI 按本文档规则把事件卡转成完整事件 JSON，字段补齐 `id`（前缀 `p_`）、`source: "player"`、`playerInput`（原文）、`reviewStatus: "pending"`，进审查队列后入池。
5. **审查**：规则同 06 文档——量级超标（attr>6、乱发钱、乱发 death）自动打回。

## 附录 B · 死亡叙述（本地 AI 接口）

死亡文案由三级解析产出，AI 生成事件时只需保证第一级：**事件写明 `effects.death` 死因短语**。其余两级（世界死因池、通用兜底）由引擎处理。
后续接入本地 AI 时，引擎会把 `DeathContext { kind, cause, age, worldId, tags, history 最近5条 }` 交给本地模型润色一句收束文案，只影响展示、不参与判定。生成事件时不需要为此做任何额外字段。
