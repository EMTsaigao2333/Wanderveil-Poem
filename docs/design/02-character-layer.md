## 1. 定位

人物构建层是**全随机模式专有**的数据层，回答「这一局你抽到了谁」。

三个出口：

1. **数据出口** → 特质直接定义六维（不经语义键中间层）
2. **叙事出口** → 标签 / 能力标签，供事件 `require` 门槛
3. **视觉出口** → `promptTags` / `moodTags` / `promptNegative`，供人生总结图与二期立绘生成

> **事件效果仍走语义键**（`Effects.attr`），**特质走六维偏移向量**。两条路径互不干扰。

## 2. 特质三分类（按获取路径）

这是本层最核心的规则。同一个特质可以同时挂在多条路径上。

| 类型 | 获取方式 | `full` 生到死 | `episodic` 片段 | 例子 |
|---|---|---|---|---|
| **先天型** `innate` | 转盘概率抽取 | 抽到 = 天生如此；**抽不到就没有** | 开局抽取 | 外貌、体型、天赋、先天失明、天生敏感 |
| **后天型** `acquired` | 事件触发 | **只能由事件获得**（事故 → 失明） | 可开局携带，也可事件获得 | 后天失明、截肢、PTSD、成瘾 |
| **状态型** `state` | 环境反馈累积 | 不抽取，从基线随事件增减 | 可带初始值 | 心理韧性、信任感、自我价值、压抑度 |

**失明的规则验证**（用户原话）：

- 成长故事（`full`）抽到失明 → 先天；没抽到 → 后续可能由事件后天失明
- 片段故事（`episodic`）→ 先天与后天都可开局存在

落地：`TraitOption.paths: TraitPath[]`，转盘池按 `lifeModel` 过滤：

| lifeModel | 可进开局池的路径 |
|---|---|
| `full` | 仅 `innate` |
| `episodic` | `innate` + `acquired` |

## 3. 数据结构

```ts
/** 特质槽位 */
export type TraitSlot =
  // —— 主线槽（逐个定格，必抽）——
  | 'gender'       // 性别
  | 'height'       // 身高
  | 'build'        // 体型
  | 'hair'         // 发色
  | 'eye'          // 瞳色（含异瞳）
  | 'vision'       // 视力（正常 / 先天失明 / 后天失明）
  | 'looks'        // 容貌
  | 'personality'  // 性格
  | 'morality'     // 道德水平
  | 'origin'       // 出身
  | 'startAge'     // 起始年龄（仅 episodic）
  // —— 副线池（命运牌，概率抽）——
  | 'bodyForm'     // 生理·形态
  | 'bodyFunc'     // 生理·机能
  | 'psyche'       // 心理·人格
  | 'psycheClinic' // 心理·病理
  | 'aptitude'     // 天赋才能
  | 'social';      // 社会细项

/** 获取路径 */
export type TraitPath = 'innate' | 'acquired' | 'state';

/** 六维偏移向量（特质直接定义六维） */
export interface SixOffset {
  insight?: number;
  resolve?: number;
  empathy?: number;
  ingenuity?: number;
  reverie?: number;
  vitality?: number;
}

export type TraitRarity = 'common' | 'rare' | 'epic' | 'curse';

/** 特质的一档（有强度分档时使用；偏移 / 文案 / 提示词均按档独立存） */
export interface TraitTier {
  /** 档位，从 1 开始，越大越重 */
  level: number;
  /** 本档显示名，例：「长久的低潮」 */
  name: string;
  /** 本档描述 */
  desc: string;
  /** 本档六维偏移 */
  offset: SixOffset;
  /** 本档正向提示词（绘图 AI 可见实体） */
  promptTags: string[];
  /** 本档反向提示词（防止 AI「修复」特征） */
  promptNegative: string[];
  /** 本档气质氛围提示词 */
  moodTags: string[];
}

/** 特质的可视化信息（总结图用，P0 不用于立绘） */
export interface TraitVisual {
  color?: string;
  color2?: string;
  value?: number;
  glyph?: string;
  badge?: string;
}

/** 特质的高危性标记 */
export interface TraitSafety {
  /** 是否属敏感内容（残疾 / 病理 / 成瘾），可在设置中关闭 */
  sensitive: boolean;
  /** 展示用的中性文案，避免病理标签污名化 */
  neutralLabel?: string;
}

export interface TraitOption {
  id: string;
  name: string;
  desc: string;
  slot: TraitSlot;
  /** 获取路径，可多条 */
  paths: TraitPath[];
  rarity: TraitRarity;
  weight?: number;
  /** 数值预算成本，默认按稀有度（common 1 / rare 2 / epic 3 / curse -1） */
  cost?: number;

  /** 无分档时直接使用；有分档时以 tiers 为准 */
  offset?: SixOffset;
  /** 有强度分档的特质（如抑郁轻/中/重）；每档偏移与提示词独立存 */
  tiers?: TraitTier[];

  /** 无分档时的正向提示词 */
  promptTags?: string[];
  /** 无分档时的反向提示词 */
  promptNegative?: string[];
  /** 无分档时的气质氛围提示词 */
  moodTags?: string[];

  /** 特质标签，供事件 require.tags 使用，如 '性格_内向' */
  tags?: string[];
  /** 能力标签，供事件 require.caps 使用，如 'blind' 'wheelchair' */
  caps?: string[];
  /** 可视化信息 */
  visual?: TraitVisual;
  /** 解锁规则：控制该特质在何种局面下可用 */
  unlock?: TraitUnlock;
  /** 敏感内容标记 */
  safety?: TraitSafety;
  /** 归属世界；'*' 表示通用池 */
  world: string;
}

/** 解锁规则 */
export interface TraitUnlock {
  /** 仅在这些人生模型下可入开局池 */
  models?: ('full' | 'episodic')[];
  /** 该特质只能后天获得（等价于 paths 只含 'acquired'） */
  acquiredOnly?: boolean;
  /** 最小出现年龄 */
  minAge?: number;
  /** 心理病理：需压抑度达到阈值才可触发 */
  requiresSuppression?: number;
}

/** 槽位定义 */
export interface TraitSlotDef {
  slot: TraitSlot;
  name: string;
  /** 该槽抽取个数，默认 1 */
  picks: number;
  /** 该槽是否必抽（主线槽 true；副线槽由 poolChance 决定） */
  required: boolean;
  /** 副线池的抽中概率（0~1），required=false 时生效 */
  poolChance?: number;
}

/** 特质池：一个世界一套 */
export interface TraitPool {
  world: string;
  /** 槽位顺序 = 转盘定格顺序 */
  slots: TraitSlotDef[];
  options: TraitOption[];
  /** 六维基线，建议每维 6 */
  baseline: SixOffset;
  /** 数值预算上限，防超模 */
  budgetCap: number;
  /** 六维合法区间 */
  range: [number, number];
  /** 心理状态量基线 */
  psycheBaseline: PsycheState;
}

/** 人物卡：转盘抽完的结果，是 RunState 的一部分 */
export interface CharacterCard {
  seed: number;
  /** 槽位 → 抽中的特质 id */
  slots: Partial<Record<TraitSlot, string[]>>;
  /** 展开后的特质 */
  traits: TraitOption[];
  /** 最终六维 */
  six: SixOffset;
  /** 开局心理状态量 */
  psyche: PsycheState;
  budgetUsed: number;
  tags: string[];
  caps: string[];
  /** 文字版人物卡（P0 主要呈现形式） */
  summaryText: string;
}
```

## 4. 心理状态量（状态型）

心理**不是有/无的标签，而是可累积、可释放的数值**。

```ts
export interface PsycheState {
  /** 韧性：抗打击能力 */
  resilience: number;
  /** 信任：对他人的开放度 */
  trust: number;
  /** 自我价值 */
  selfWorth: number;
  /** 压抑度：累积未释放的创伤 */
  suppression: number;
  /** 已触发的临床病理（后天型特质 id） */
  conditions: string[];
}
```

### 事件如何影响它

同一事件、两个选项，方向相反（用户例子：母亲离开）：

| 选项 | Effects |
|---|---|
| 藏起来当没发生过 | `psyche: { suppression: +2, trust: -1 }` |
| 找到亲密的人大哭一场 | `psyche: { suppression: -3, trust: +1, resilience: +1 }` |

需在 `schema.ts` 的 `Effects` 中新增：

```ts
export interface Effects {
  // ...原有字段
  /** 心理状态量增减 */
  psyche?: Partial<Record<keyof Omit<PsycheState, 'conditions'>, number>>;
}
```

### 病理触发（阈值自动 + 可分档加重）

```
每年（或每次重大事件后）结算：
  若 suppression ≥ TIER1 阈值 → 触发心理病理档 1（如「长久的低潮」）
  若 suppression ≥ TIER2 阈值 → 升档到 2
  若 suppression ≥ TIER3 阈值 → 升档到 3
  若 suppression 回落至阈值以下（如被陪伴释放）
    → 档位降级；长期低于阈值 → 病理移除（conditions 移除该 id）
```

阈值（已确认）：

| 档 | suppression 阈值 |
|---|---|
| 1 轻度 | ≥ 8 |
| 2 中度 | ≥ 14 |
| 3 重度 | ≥ 20 |

## 5. 特质互斥（先天 vs 后天）

同一件事可能被先天型与后天型分别描述（都是失明）。规则：**同一特质互斥，抽到就不再叠加**。

```ts
/** 互斥组：同组内只允许存在一个 */
export const TRAIT_EXCLUSIVE_GROUP: Record<string, string[]> = {
  vision_blind: ['vision_blind_innate', 'vision_blind_acquired'],  // 失明
  limb_missing: ['limb_missing_innate', 'limb_missing_acquired'],  // 缺肢
  // ...
};
```

引擎在 `gainTraits` 时检查：若本组内已有特质，则忽略本次获得（或按规则替换）。开局抽卡阶段同样遵守。

## 6. 合成规则（基线 + 偏移求和）

```
1. six = { ...pool.baseline }                      // 起点：每维 6
2. 对每个抽中的特质：
     若有 tiers → 取当前档的 offset
     否则 → 取 offset
     six[k] += 该 offset[k]
3. 预算校验：Σ cost ≤ pool.budgetCap
     超预算 → 重抽成本最高的非必需特质（最多重试 20 次）
4. clamp：每维限制在 pool.range = [0, 20]
5. 心理状态量：psyche = { ...pool.psycheBaseline }（再叠加特质修正）
6. 记录 budgetUsed
```

**设计取舍**：不采用「六维总和固定」，用「预算上限 + 区间 clamp」。
理由：总和固定会让所有开局强度趋同，削弱全随机的乐趣；预算上限只拦「超人/废人」。

## 7. 特质人生中改写

需在 `schema.ts` 的 `Effects` 中新增：

```ts
export interface Effects {
  // ...原有字段
  gainTraits?: string[];
  loseTraits?: string[];
  gainCaps?: string[];
  loseCaps?: string[];
}
```

| 场景 | 写法 |
|---|---|
| 事故后失明 | `{ gainTraits: ['vision_blind_acquired'], gainCaps: ['blind'] }` |
| 性格被磨平 | `{ loseTraits: ['personality_passionate'], gainTraits: ['personality_calm'] }` |
| 抑郁缓解 | `{ loseTraits: ['depression_lv2'], gainTraits: ['depression_lv1'] }`（由状态量结算自动处理） |

### 7.1 改写时的六维结算规则

特质改写**要加减六维**，但不整体重算 —— 六维是「基线 + 全部偏移求和」的合成结果，人生中被改掉的只是**这一条特质贡献的那部分**：

| 动作 | 六维处理 |
|---|---|
| 获得特质 | `六维 += 该特质 offset` |
| 失去特质 | `六维 -= 该特质 offset` |
| 分档升降（lv1 → lv2） | `六维 += (新档 offset − 旧档 offset)`，即只补差额 |
| 每次改动后 | clamp 到 `COMMON_RANGE`（0~20） |

> 举例：中年因事故失明，不是把六维从头算一遍，而是把 `vision_blind_acquired` 的 `offset`（洞见 −2 / 通感 −1 / 行力 −1）叠加到当前值上 —— 前半生积累的能力被保留，只是从此多了这份代价。
>
> 这样做的两个好处：① 已发生的人生不会被后来的特质「改写历史」；② 开局强度差异与中期成长曲线都能保住。

### 7.2 三类「后天代价」的分工（2026-10-08 新增）

人生里的负面结果有三种载体，**职责不同，不要混用**：

| 载体 | 例子 | 特点 | 归谁管 |
|---|---|---|---|
| **特质**（`gainTraits`） | 后天失明、记忆编辑痕迹 | **永久**、**有六维偏移**、**可带 caps 改变能力门槛分支** | 本节 7.1 |
| **标签**（`tags`） | 「右肩抬不起来」「摔断过骨头」 | **永久**、无数值影响、**长出因果支线**（供后续 `require` 使用） | 02 文档第 12 节 |
| **伤势**（`Debuff`，新增） | 肋骨未愈、慢性炎症、工伤后遗症 | **有时限**、**持续啃属性**、**需要花钱/休养才能好** | [09 文档](./09-fatality-and-consequence.md) 第 5 节 |

**选哪个的判断法则**：

1. 这件事**改变了这个人是什么**（失明、成瘾、病理）→ 用**特质**；
2. 这件事**只是发生过**，但以后还会被提起（摔断过骨头、手上的疤）→ 用**标签**；
3. 这件事**正在持续消耗这个人**（肋骨未愈、慢性排异、工伤后遗症）→ 用**伤势**。

> 为什么必须有第三类：实测「一次性 −5 行力」在 3 步内被后续事件补回来的比例是 **90%**（见 09 文档第 1 节），
> 也就是说**纯数值惩罚会被冲掉**。伤势的价值在于它**每年都在扣**，玩家必须主动处理才能止血。

> **代价写在哪（2026-10-08 补充）**：上面三类代价在事件数据里的**统一承载位置**是 `Outcome.cost`
> （`success.cost` = 成功但有代价；`fail.cost` = 失败的额外代价），可用 `costUnless: 'critSuccess'` 表示大成功时免除。
> 完整语义与结算顺序见 [10 文档](./10-outcome-and-attribute-rebalance.md) 第 2 节。

## 8. 完整特质分类树

### 已覆盖（主线槽）

性别 · 身高 · 体型 · 发色 · 瞳色（含异瞳）· 视力（含失明）· 容貌 · 性格 · 道德 · 出身

### A. 生理·形态 `bodyForm`（视觉可见）

| 子类 | 候选 |
|---|---|
| 面部 | 脸型（圆/方/尖）、雀斑、胎记、面部疤痕、痣、痘印 |
| 毛发 | 发量（浓密/稀疏/早秃）、发质（直/波浪/卷/粗硬/细软）、体毛多少、白发早生 |
| 眼睛（形象） | 眼型（杏眼/丹凤/下垂/上挑）、黑眼圈、眼袋 |
| 牙齿 | 龅牙 / 缺牙 / 牙套 / 烟渍 |
| 皮肤 | 肤色（深浅/冷调/暖调）、疤痕体质、白癜风、银屑病、敏感肌 |
| 年龄感 | 娃娃脸 / 显老 / 早衰 |

### B. 生理·机能 `bodyFunc`（半可见）

| 子类 | 候选 |
|---|---|
| 听力 | 正常 / 弱听 / 单耳失聪 / 全聋 |
| 言语 | 正常 / 口吃 / 沙哑 / 失语 / 嗓音特殊 |
| 嗅觉味觉 | 正常 / 失灵 / 过敏 |
| 触觉痛觉 | 正常 / 痛觉迟钝 / 痛觉过敏 / 先天性无痛症 |
| 运动 | 协调 / 笨拙 / 运动天赋 / 平衡感差 |
| **肢体** | **完整 / 缺肢（上肢单双侧、下肢单双侧）/ 截瘫 / 偏瘫 / 脊柱侧弯 / 关节病 / 义肢（世界相关）** |
| 内脏慢性 | 强健 / 体弱 / 哮喘 / 心脏病 / 糖尿病 / 癫痫 / 偏头痛 / 胃病 / 过敏体质 |
| 神经系统 | 抽动症 / 震颤 / 面瘫 |
| 免疫 | 免疫低下 / 自体免疫病 |

### C. 心理·人格 `psyche`（正常范围）

| 子类 | 候选 |
|---|---|
| 大五人格 | 开放性、尽责性、外向性、宜人性、神经质（各分高低） |
| 气质 | 乐观 / 悲观 / 愤世嫉俗 / 天真 / 多疑 |
| 意志 | 坚毅 / 易放弃 / 拖延 / 高度自律 |
| 攻击性 | 温和 / 易怒 / 好斗 / 极度压抑 |
| 社交 | 社交恐惧 / 社交自如 / 讨好型 / 疏离型 / 控制欲强 |

### D. 心理·病理 `psycheClinic`（临床，分档）

| 子类 | 候选 |
|---|---|
| 情绪障碍 | 抑郁（轻/中/重）、双相、持续性心境低落、季节性抑郁 |
| 焦虑谱系 | 广泛性焦虑、惊恐障碍、社交焦虑、特定恐惧症（幽闭/恐高/血/动物） |
| 创伤相关 | PTSD、解离、闪回、情感麻木 |
| 强迫相关 | OCD、囤积、拔毛癖 |
| 进食 | 厌食症、暴食症 |
| 睡眠 | 失眠、嗜睡、梦游、夜惊、噩梦频繁 |
| 成瘾 | 酒精 / 药物 / 尼古丁 / 赌博 / 游戏 |
| 神经发育 | ADHD、自闭谱系、阅读障碍、计算障碍、脸盲、超强记忆、联觉 |
| 人格障碍（重度·`curse`） | 边缘型、偏执型、回避型、自恋型、反社会 |
| 躯体化 | 疑病症、慢性疼痛 |

> 本池全部标 `safety.sensitive = true`，并优先使用 `neutralLabel`（现象化文案）。
>
> **分档策略**：只有情绪 / 焦虑 / 创伤 / 强迫 / 睡眠 / 成瘾这几支拆 3 档（严重度天然是连续的）；恐惧症、神经发育、躯体化、人格障碍不拆档，严重度变化交给心理状态量表达。详见 15.1。
>
> **归属**：本池几乎全部是**后天型**（`acquired`），需 `suppression` 达标才触发；只有恐惧症与神经发育类保留先天路径。「超强记忆」「联觉」不属于病理，已移入 E 组。

### E. 天赋才能 `aptitude`

艺术（绘画/音乐/写作）、数理、语言、机械手工艺、共情天赋、记忆天赋、方向感、味觉天赋、联觉、节奏感、模仿、表演、谈判

### F. 社会细项 `social`

## 9. 提示词规范

特质按视觉性分三类，各自带不同提示词。**有分档的特质，每档独立存一份**。

| 类型 | 例子 | 字段 |
|---|---|---|
| 视觉可见 | 发色、截肢、轮椅、疤痕、纹身、肥胖 | `promptTags`：英文实体词，如 `wheelchair` / `prosthetic_left_arm` / `facial_scar` |
| 视觉半可见 | 性格、道德、心理 | `moodTags`：气质氛围，如 `melancholic` / `stoic` / `nervous` |
| 视觉不可见 | 色盲、慢性病、信仰 | 不填，只在文案体现 |

**`promptNegative` 是必须的**：绘图 AI 有强烈的「补全残障」倾向——不加反向词，会把轮椅画成健全的双腿、把疤痕修掉。示例：

```ts
{
  id: 'limb_missing_lower',
  promptTags: ['wheelchair', 'missing_both_legs', 'amputee'],
  promptNegative: ['full_body_intact', 'walking', 'standing_legs'],
  moodTags: ['determined'],
}
```

### 分档示例（抑郁）

| 档 | neutralLabel | offset | promptTags | moodTags |
|---|---|---|---|---|
| 1 | 长久的低潮 | `resolve -1, empathy +1` | `tired_eyes, slight_frown` | `melancholic` |
| 2 | 提不起力气 | `resolve -2, vitality -1` | `heavy_eyebags, unkempt_hair` | `listless, withdrawn` |
| 3 | 连呼吸都累 | `resolve -4, vitality -3` | `gaunt_face, hospital_gown, bedridden` | `hollow, desolate` |

> **P0 不做立绘，但字段现在就存，成本几乎为零**；二期做立绘时直接从数据拼提示词，省一次全量返工。

## 10. 敏感内容处理

### 10.1 两级内容标记（数据侧）

| 级别 | 字段 | 覆盖内容 | 默认 | 权重系数 |
|---|---|---|---|---|
| 重敏感 | `safety.sensitive = true` | 心理病理 / 残疾 / 成瘾 / 重疾 —— 会直接改变命运走向的沉重内容 | **关闭** | ×0.3 |
| 轻不适 | `safety.tender = true` | 肥胖 / 丑陋 / 龅牙 / 体毛 / 口吃 / 孤儿 / 单亲 / 少数族裔等「让人不舒服但不致命」的内容 | **关闭** | ×0.5 |
| 普通 | 两者都不标 | 其余特质 | 开启 | ×1.0 |

两级**都默认关闭** —— 默认体验下人物是「平凡的身体 + 中性的处境」，不会一开局就被抽到残疾或病理。

### 10.2 内容偏好面板（开局向导内，见 07 文档）

在开局向导的**显眼位置**（不藏进二级菜单）放「内容偏好」面板：

- 顶部一句话说明：**「以下内容默认关闭。想让这段人生更有戏剧性，可以按类别或逐条打开。」**
- 面板支持**按类别整组开关** + **单条勾选**（例：只开「肥胖」「丑陋」，不开「残疾」「成瘾」）
- 分组依据是 `safety.category`，建议 9 类：`looks` 外貌 / `senses` 感官 / `limbs` 肢体 / `internal` 内脏慢病 / `neuro` 神经 / `psyche` 心理病理 / `addiction` 成瘾 / `family` 家庭处境 / `origin` 族裔教育
- 结果存进玩家偏好（本地），下次开局沿用

> 代码侧：`ContentPrefs`（`{ sensitive?: string[]; tender?: string[] }`）交给 `canEnterOpeningPool()`；面板用 `groupByCategory()` 一次取全分组。

### 10.3 为什么不做「一个总开关」

一刀切两头都伤：默认全开 → 一上来就被抽到残疾，毁掉这一局；只给一个总开关 → 想开的人必须照单全收。所以粒度做到**类别 + 单条**。

### 10.4 池空即「无」

默认设置下，`psycheClinic` 池（43 条全是病理）与 `bodyFunc` 池（40 条里 30+ 条带标记）**没有可抽候选**。这不报错也不回退：副线池掷中后若候选为空，直接判定为「无」—— 与「抽不中」同一结果。默认体验因此是「平凡的出生」，符合预期。

### 10.5 开关作用域

开关**只管控开局抽取**（先天入池）。人生中由事件因果触发的病理与后天特质**不受开关影响** —— 它们来自玩家的选择与经历，屏蔽掉会让因果链断裂。

### 10.6 文案与审核

| 措施 | 说明 |
|---|---|
| 中性文案 | 用现象描述而非病理标签做展示名：不写「抑郁症」写「长久的低潮」；不写「残疾」写「左腿的高位空缺」 |
| 审核预留 | 内容标记便于过微信内容安全审核时快速排查 |

## 14. 对事件库的冲击（2026-09-24 重写，待确认）

引入 `caps`（能力标签）后，事件可声明能力门槛 —— `schema.ts` 的 `Condition` 提供两个字段：

```ts
require: { caps: ['blind'] }      // 只有失明角色能选 / 能触发（专属选项、专属事件）
require: { notCaps: ['blind'] }   // 需要看得见（纯视觉描写的选项）
```

### 14.1 唯一原则：做加法，不做减法

残疾角色**不该被拿走选项**，而应看到**专属选项、专属旁白、或另一条到达同一目的的路**：

| 写法 | 评价 |
|---|---|
| 失明者靠回声与脚步判断船舱深浅（专属选项） | ✅ 加法 |
| 轮椅走货运电梯上云台，而不是爬通风管（替代路径） | ✅ 加法 |
| 听不见的人靠读唇看清对方在撒谎（专属检定，换一个语义键） | ✅ 加法 |
| 失明者看不到线索 → 直接**少一个选项** | ❌ 减法，玩家会觉得自己被惩罚 |

**引擎层的硬约束**：同一事件里**不允许所有选项都被 `caps` 过滤掉**。引擎遇到「可见选项为 0」时会退化成「自动事件」，而自动事件若没写 `effects`，这一年就等于什么都没发生 —— 静默跳过内容是事故，不是设计。因此：

- 带 `caps` / `notCaps` 过滤的选项，**必须**在同一事件里至少留一个无门槛选项
- 想让残疾角色得到更好的结果，用「专属选项 + 更高档位」，而不是砍掉别人的路

### 14.2 本次要补的三类（优先级最高）

| 能力标签 | 覆盖对象 | 分支形式 |
|---|---|---|
| `blind` | 先天失明 / 后天失明（含事件造成的） | 专属选项 + 专属事件（回声、触感、他人描述） |
| `wheelchair` | 缺腿 / 截瘫（先天与后天共用） | 替代路径 + 专属事件（坡道、电梯、别人的手） |
| `deaf` | 先天耳聋 / 后天耳聋 | 专属选项 + 专属事件（读唇、手写、震动与光） |

**交付范围（本次）**：

1. **每个阶段至少 1 条专属事件**：幼年 / 少年 / 青年 / 壮年 / 中年 / 老年各 1~2 条，按上面的三类分配（合计 ≥ 8 条，赛博朋克）
2. **在 4~6 条现有事件里插入专属选项**（不新建事件），例如废船坞深舱、云台上行、黑场拳赛、最后的雨

> **交付记录（2026-09-24）**：已交付 9 条专属事件（盲 3 / 轮椅 4 / 聋 2，六个阶段各有 ≥1）+ 7 条现有事件追加专属选项（`cb_child_007` 酸雨 · `cb_child_016` 观景窗 · `cb_teen_002` 废船坞 · `cb_teen_026` 上去看一眼 · `cb_youth_010` 黑拳 · `cb_mid_016` 最后一次接入 · `cb_eld_018` 最后的雨）。
> 验收结果：**11 项断言全通过** —— 无任何事件的所有选项被门槛挡掉；三种残疾各有 ≥2 条专属事件；端到端模拟中盲 25/25 局、轮椅 25/25 局、聋 22/25 局遇到了专属事件，而普通角色一局都没看到。
> 已知的小限制：`cb_teen_026`（`chance 0.6`）与 `cb_mid_016`（需「拿着根密钥」）的前置较窄，追加的选项在部分局里见不到 —— 属可接受的加分路径，其余 5 条覆盖常见前置。

### 14.3 其余能力标签（沿用同一模板，后补）

已具备 `caps` 的还有：`monocular` 单眼、`hard_of_hearing` 弱听、`single_side_deaf` 单耳失聪、`stutter` 口吃、`mute` 失语、`missing_arm` 缺臂、`short_stature` 侏儒症、`colorblind` / `nightblind` 色盲夜盲、`asthma` 哮喘、`heart_condition` 心脏病、`diabetes` 糖尿病、`epilepsy` 癫痫、`pain_insensitive` 无痛症、`claustrophobia` 幽闭恐惧、`acrophobia` 恐高、`prosopagnosia` 脸盲等 —— 按 14.1 的加法原则分批补，**不阻塞引擎与 UI**。

### 14.4 与「内容偏好开关」的关系

**能力分支不受内容偏好开关影响。** 开关只管**开局抽取**（默认关掉敏感与轻不适特质）；一旦残疾是**后天由事件因果造成的**（事故、义体事故、暴力），玩家一定会遇到这些分支 —— 这正是「因果链」的兑现处，不能因为关过开关就消失。

### 14.5 文案要求

中性、不怜悯、不励志化。写「换一条路」，不写「克服困难」；写具体动作（怎么上坡、怎么听见），不写情绪总结。与 02 文档第 9 节的文风要求一致。

## 11. 稀有度与概率设计

**原则：现实中不常发生的负面特质，概率必须小。** 不做逐条手工调参，用一条数据驱动的统一规则：

```
最终抽取权重 = (trait.weight ?? RARITY_WEIGHT[rarity]) × 安全系数
安全系数 = trait.safety?.sensitive ? 0.3 : 1.0
```

| 类型 | 稀有度 | 基础权重 | 安全系数 | 实际权重 |
|---|---|---|---|---|
| 常态特质 | `common` | 8 | 1.0 | 8 |
| 明显优势 | `rare` | 4 | 1.0 | 4 |
| 极端优势 | `epic` | 1.5 | 1.0 | 1.5 |
| 敏感·负面 | `curse` | 2 | **0.3** | **0.6** |
| 敏感·临床病理（轻度） | `common` | 8 | **0.3** | **2.4** |

**效果**：以副线池「心理·病理」为例，池内约 25 条。重度项（人格障碍）实际权重 0.6、轻度项（失眠、焦虑）2.4——玩家的抽中概率自然向轻度倾斜，**重度项成为真正的「命运」**，无需逐条调参。

> 这一条同时适用于主线槽与副线池（见 [05-roulette-mode.md](./05-roulette-mode.md) 第 2 节）。

## 12. 因果关系与选项可用性

**核心规则：选项的存在来自过去的因果，不存在「人人都有」的选项。**

用户原话：

> 我小的时候没有关系好的人，那就无法产生另一个选项

落地方式：**不新建「关系账本」系统**，用现有机制组合表达——

| 机制 | 作用 |
|---|---|
| `tags` | 沉淀因果（如 `has_close_friend`、`母_缺席`、`曾被背叛`） |
| `Choice.require` | 用标签门槛控制选项是否出现 |
| `PsycheState` | 提供量化心理代理（`trust` 高才敢向人倾诉） |
| `relations` | 记录具体羁绊对象及其状态（见 [03-runstate-save.md](./03-runstate-save.md)） |

**作者写法示例**：

```ts
{
  id: 'cb_teen_012',
  stage: 'teen',
  text: '母亲离开的那个雨夜，你没有告诉任何人。',
  choices: [
    {
      label: '把它藏起来，当作没有发生过',
      effects: { psyche: { suppression: +2, trust: -1 } },
    },
    {
      label: '跑去找那个人，大哭一场',
      require: { tags: ['has_close_friend'] },   // 因果前置：必须先有关系好的人
      effects: { psyche: { suppression: -3, trust: +1, resilience: +1 } },
    },
  ],
}
```

### 作者的职责边界

| 必须写 | 不必写 |
|---|---|
| 事件中**有因果前置**的选项，挂 `require` | 无差别给每个事件都加 `psyche` 效果 |
| 涉及创伤 / 丧失 / 背叛的**关键节点**，给 `psyche` 方向 | 日常琐事事件 |
| 会**沉淀标签**的选项，给 `Effects.tags` | 一次性的过场事件 |

> **修正说明**：此前「146 条事件都要补 `psyche` 效果」的说法过度了。**只有有因果联系的节点才需要**——这正是本节的规则。

## 13. 玩家自定义选项（P2）

| 层级 | 形态 | 期次 |
|---|---|---|
| 轻量 | 在既有事件中提出**自定义线路**，或**新增一个选项** | P2（见 06 文档） |
