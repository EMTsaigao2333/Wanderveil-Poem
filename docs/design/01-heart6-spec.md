## 1. 六维定义

六维是「内在禀赋」系统，**不含外貌与家境**（那两项在六维系统下走开局背景词条，在全随机模式下走人物卡特质）。

| 维度 | key | 内核 | 现实题材 | 奇幻题材 | 其他题材 |
|---|---|---|---|---|---|
| **洞见** | `insight` | 观察力 · 判断力 · 信息捕捉 | 识破谎言 | 发现魔法破绽 | 悬疑：找到线索 |
| **持守** | `resolve` | 意志力 · 抗压性 · 执念 | 扛住事业挫折 | 抵抗精神污染 | 恐怖：维持理智 |
| **通感** | `empathy` | 共情力 · 人际感知 · 情绪共鸣 | 说服他人 | 与异族沟通 | 古风：笼络人心 |
| **机变** | `ingenuity` | 临场反应 · 变通能力 · 应急智慧 | 化解商业危机 | 临时躲技能 | 古风：朝堂应变 |
| **遐思** | `reverie` | 想象力 · 直觉 · 对非常规事物的接受度 | 创意灵感 | 感知魔力 | 悬疑：预感危险 |
| **行力** | `vitality` | 行动力 · 执行力 · 身体耐受度 | 奔波创业 | 体力续航 | 古风：长途跋涉 |

数值区间统一 `0 ~ 20`，初始值由各世界的生成方式决定（六维系统 = 开局分配；全随机模式 = 特质推导）。

## 2. 与语义键的对应关系

事件库只写语义键（`SemanticAttr`），由 `HEART6.map` 折算到六维。对应关系如下：

| 语义键 | 含义 | 折算到 |
|---|---|---|
| `perception` | 感知 / 洞察 | `insight` 洞见 ×1 |
| `will` | 意志 / 持守 | `resolve` 持守 ×1 |
| `empathy` | 共情 / 通感 | `empathy` 通感 ×1 |
| `ingenuity` | 应变 / 机变 | `ingenuity` 机变 ×1 |
| `reverie` | 灵感 / 遐思 | `reverie` 遐思 ×1 |
| `vitality` | 行动 / 行力 | `vitality` 行力 ×1 |
| `health` | 身体 | `vitality` 行力 ×1 **（本次变更，见第 3 节）** |
| `mood` | 心境 | `resolve` 0.5 + `reverie` 0.5 |
| `charm` | 外在魅力 | `'background'`（背景词条评分） |
| `wealth` | 家资 | `'background'`（背景词条评分） |

## 3. 归属重划（本次变更）

因新定义中**行力明确包含「身体耐受度」**，`health` 语义键的落点需要调整：

| 语义键 | 旧归属 | 新归属 | 原因 |
|---|---|---|---|
| `health` | `{ vitality: 0.6, resolve: 0.4 }` | `{ vitality: 1 }` | 「身体耐受度」已归入行力；持守的内核是意志力与抗压性，属精神层面，不应由身体分摊 |

> 影响：需同步修改 `miniprogram/data/attributes.ts` 中 `HEART6.map.health`。该改动会轻微提升「行力」在事件结算中的涨幅、降低「持守」涨幅，属预期内。
> **已确认（2026-09-23）：按提案执行**，`HEART6.map.health = { vitality: 1 }`。

## 4. 检定用法

统一规则（`CHECK_RULE`）：

```
掷 1d20 + floor(属性值 / 2) ≥ DC  →  成功
骰面 = 20 → 大成功（success 结果强化）
骰面 = 1  → 大失败（fail 结果加剧）
```

难度档（`DC`）：

| 档位 | DC | 适用 |
|---|---|---|
| easy | 10 | 日常、无风险倾向的尝试 |
| normal | 13 | 标准抉择 |
| hard | 16 | 高风险、需专长 |
| extreme | 19 | 极端情境、翻盘 |

### 4.1 大成功 / 大失败的结算（2026-09-24 新增，待确认）

骰面 20 / 1 不只是「更强的成功 / 更惨的失败」，而是**结果数值的强化**：

| 结果 | 走哪条分支 | 数值口径 |
|---|---|---|
| 大成功（骰面 20） | 作者的 `success` 分支 | 顺着玩家的那一半 **×1.5**、逆着的那一半 **×0.5**（至少 ±1） |
| 大失败（骰面 1） | 作者的 `fail` 分支 | 逆着玩家的那一半 **×1.5**、顺着的那一半 **×0.5**（至少 ±1） |

口径细节：

- **参与缩放**：语义属性、金钱、背景词条评分、心理状态量
- **不参与缩放**：标签 `tags`、特质增删 `gainTraits` / `loseTraits`、能力 `caps`、生死 `death` —— 这些是作者写死的因果，不该被一个骰面改写
- 文案由引擎补一层语气（大成功加「你做得远比想象中好」，大失败加「而事情正往最坏的方向滑去」），作者仍只写 `success` / `fail`

**重点选项（`Choice.major`）** —— 会决定这段人生走向的抉择（成为传奇 / 对抗大企业 / 出卖同伴 / 把命押上桌）标 `major: true`，并可另写两条专用分支：

```ts
{
  label: '换',
  check: { attr: 'vitality', dc: DC.hard },
  major: true,
  success: { text: '...', effects: { attr: { vitality: 3 } } },
  fail: { text: '...', effects: { attr: { health: -5 } } },
  critSuccess: { text: '...', effects: { money: 50000, tags: ['跑得过巡逻机'] } },
  critFail: { text: '...', effects: { death: '神经脊在你体内熔断了。' } },  // 可以直接终结人生
}
```

- 写了专用分支 → 大成功 / 大失败**完全按作者写的走**（可含 `death`，即「一骰决定生死」）

> **⚠ 2026-10-08 补充（待确认）**：本节定义了「大成功/大失败怎么结算」，但**没有定义"死亡该挂在哪一档"**。
> 实测结果：全库 5 处 `death` 全部挂在 `critFail` 上，统一 5% 概率 —— 于是「卷入重工机器」和「摔一跤」的威胁等级完全一样。
> 死亡的分级、事故致死率、以及"普通失败能不能致死"，现在统一由 [09 致死档位与失败代价](./09-fatality-and-consequence.md) 定义：
> - **死亡分五档**（寿终 / 衰竭 / 抉择致死 / 事故致死 / 慢性致死）
> - **事故按 `hazard` 危险等级分档**（`none` / `low` / `mid` / `high` / `lethal`），大失败致死率上限 35%
> - **普通失败默认不致死**，只有 `hazard: 'lethal'` 且显式声明 `failLethal` 时才可能
> - **失败必须留下持久代价**（伤势 `Debuff` + 永久标签 + 小概率残疾）
>
> 本节第 90 行「生死不参与缩放」的规则不变：**死亡永远由作者写死，不由骰面倍率生成**。

> **⚠ 2026-10-08 两处补充（待确认）**：
> 1. **`floor(属性/2)` 的检定修正保留、不要改成「属性直接入检定」**。实测：`floor(属性/2)` + 上限 20 时，运气跨度 : 能力跨度 = **1.9 : 1**（可用）；改成属性直接入检定、上限 20 变成 **0.95 : 1**，上限 30 更是 **0.63 : 1**（骰子几乎不起作用，检定失去张力）。详见 [10 文档](./10-outcome-and-attribute-rebalance.md) §1.6。
> 2. **「成功但有代价」由 `Outcome.cost` 承载**（`success.cost` / `fail.cost`，可用 `costUnless: 'critSuccess'` 免除）。它与本文档 §4.1 的 crit 缩放**互相独立**：`cost` **不参与** ×1.5 / ×0.5 缩放（与 `tags` / `death` 同类，同第 90 行原则）。详见 [10 文档](./10-outcome-and-attribute-rebalance.md) §2。
- 没写 → 走上面的数值强化
- 界面把 `major` 选项高亮为「关键抉择」（P0-5 接）

**属性 → 检定的选取指引**（事件作者按此选 `Check.attr` 的语义键）：

| 情境 | 用哪个语义键 |
|---|---|
| 看穿伪装、找出破绽、发现线索 | `perception` |
| 顶住压力、抵抗侵蚀、维持理智 | `will` |
| 说服、安抚、笼络、沟通 | `empathy` |
| 临场应变、脱身、化解危机 | `ingenuity` |
| 灵感、直觉、预感、与异象/魔力交互 | `reverie` |
| 长途奔波、体力消耗、主动出击 | `vitality` |
| 身体损耗、伤病 | `health` |
| 精神状态、幸福感 | `mood` |

## 5. 题材标签（genre）

为了让事件作者快速判断「该用哪个维度」，世界元数据需声明题材标签（详见 `04-life-model.md`）：

`realistic` 现实 / `fantasy` 奇幻 / `mystery` 悬疑 / `horror` 恐怖 / `ancient` 古风

同一维度在不同题材下的检定对象不同（见第 1 节表格），但**结算公式完全一致**，题材只影响作者的写法与文案，不影响引擎。

## 6. 时间漂移与寿命档位（2026-09-24 新增，待确认）

`TIME_DRIFT`（`miniprogram/data/attributes.ts`）写在语义键上、**所有世界共用一张表**；具体活多久，由各世界的事件内容决定。本节取代 2026-09-23 的首版曲线（当时 40 岁起 −0.5/−0.5、75 岁后加速，实测落在 55/76/85）。

### 6.1 设计意图：寿命由「活法」决定，不由时间决定

以赛博朋克（雾港）为例 —— 底层本就不长寿，活得久是一种**经营结果**：

| 活法 | 条件 | 目标寿命 |
|---|---|---|
| 普通底层 | 没有帮派关系、也没有自己的营生 | **40 岁前后** |
| 立住一条 | 帮派关系 **或** 自己的小生意（其一） | **55 岁前后** |
| 两条都立住 | 帮派关系 **＋** 自己的小生意 | **60 岁前后** |
| 改造者 | 义体改造 **＋** 上面两条都立住 | **65 岁往后** |

- **义体改造本身不延寿**：维护义体要钱、要门路、要医生，只有同时立住帮派与营生的人才换得起 —— 所以「改造」这一档必须叠加前两项
- 走「传奇路线」（替人顶罪、对抗企业、大额劫案、重度接入）的事件会持续扣行力与身体，实际上很难活到上面任何一档
- **老年（61+）内容因此成为顶层玩家的专属回报**：普通玩家一生看不到老年事件 —— 做 UI、总结图、以及后续世界的事件数量规划时，都要按这个前提算，不能默认「人人都能玩到老年」

### 6.2 曲线怎么配合（首版数值，落地前必须模拟校准）

要让「什么都不经营」的人在 40 岁前后耗尽，衰减得从**二十岁**就开始：

| 语义键 | 年龄区间 | 每年 |
|---|---|---|
| `vitality` | 0~17 | +1 |
| `vitality` | **20~59** | **−0.5** |
| `vitality` | 60+ | −1.0 |
| `health` | **20~59** | **−0.25** |
| `health` | 60+ | −1.0 |

（20~59 合计约 **−0.75/年**、60+ 约 **−2/年**；魅力与认知类曲线不变）

- 事件层的对冲：中年起「帮派 / 摊子」的可反复触发日常事件各给行力·身体 **+2 / +2**，老年再给一层（需双标签）；改造者另有一条从壮年就开始的保养线（**只有「义体化 + 小生意 + 帮派」三项俱备才拿得到**）
- **验收标准**：四条寿命档位（40 / 55 / 60 / 65+）用批量模拟各自落在 ±3 岁内；只改代码不跑模拟不算完成

### 6.3 校准结果（2026-09-24 实测，480 局批量模拟）

| 活法 | 目标 | 实测（两种打法） | 结论 |
|---|---|---|---|
| 普通底层 | 40 前后 | **38 / 41** | ✅ |
| 立住一条 | 55 前后 | **58 / 55** | ✅ |
| 两条都立住 | 60 前后 | **60 / 64** | ✅ |
| 改造＋两条都立住 | 65 往后 | **85**（中位 87） | ✅（「往后」区间内；主要靠壮年起的保养线） |

- 分布是**双峰**的：经营不起来的人在三四十岁就耗尽，经营起来的人活到七八十 —— 这正是「活得久是经营结果」的预期形态
- 老年（61+/79+）事件在「两条都立住」一档只能勉强摸到，「改造＋两条」一档才是主要受众
