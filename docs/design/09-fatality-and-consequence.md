# 0.9 致死档位与失败代价（Fatality & Consequence）

> 状态：**2026-10-08 新增，待用户确认**
> 上游：`PROJECT_SYNC.md` 决策「大成功/大失败 ×1.5/×0.5」「死因三级解析」
> 关联：[01 六维规范](./01-heart6-spec.md) · [02 人物构建层](./02-character-layer.md) · [03 RunState/存档](./03-runstate-save.md) · [04 人生模型](./04-life-model.md) · [08 AI 文本规范](./08-ai-text-spec.md)
> 定位：**把「死亡」和「失败」从"一个 5% 骰面"升级为可分级、可声明、可预期的机制**，并给 AI 生成内容一套明确的写作规则。

---

## 1. 为什么要立这份文档（问题实测）

2026-10-08 实测（161 条事件 / 314 个选项，`_audit/_scratch/failcheck.mjs`）：

| 核实项 | 实测 | 问题 |
|---|---|---|
| 普通失败（`fail`）能否致死 | **0 / 314** | 引擎里 `death` 只在 `critFail` 分支生效，事故没有"轻则重伤、重则死"的表达 |
| 全库致死手段 | **只有 5 处，全在 `critFail`** | 触发概率统一 5%（骰面 = 1），无法表达"卷入重工机器多半活不下来" |
| 大失败分支总数 | **6 / 314** | **98% 的选项没有"重后果"位**，这是内容表达力最大的空洞 |
| "从高处摔下""卷入重工机器"类事件 | **库里不存在** | `cb_eld_022 高处` 是轮椅专属日常，不是坠落 |
| 失败的持久负面 | 314 个失败分支里只有 **8 个**给特质、**2 个**给能力标签 | 失败几乎不留痕 |
| **失败后的恢复速度** | 行力在 **3 步内回到失败前水平：90%** | 失败被后续事件直接冲掉，玩家体感不到代价 |
| 失败像奖励 | **31 个**失败分支净收益为正（如 `cb_youth_028` 失败给 `empathy+2, mood+1`） | "失败"反而划算，检定的张力被破坏 |

**一句话**：现在的系统会讲"你得到了什么"，不太会讲"你为此付出了什么"，更不会讲"这一次你可能活不下来"。

## 2. 死亡的五档分类（定稿）

死亡不再是"属性归零 + 剧情写死"两种，而是五档，各有明确的**作者责任**与**可预期性**。

| 档 | 名称 | 触发 | 玩家能否预见 | 作者责任 |
|---|---|---|---|---|
| **D0** | 寿终 | `age > elder[1]` 或行力/身体自然耗尽 | ✅ 能（属性面板 + 危险线） | 不需要特别写；由 `TIME_DRIFT` 与经营线决定 |
| **D1** | 衰竭 | 致命属性归零（见 §3） | ✅ 能（需 UI 给危险线） | 不需要写死；`deathCauses.byAttr` 提供文案 |
| **D2** | 抉择致死 | `Choice.major` 的 `critFail` 写明 `death` | ⚠️ 能（选项上必须标风险提示） | 必须给"不冒险"的替代选项；不得让玩家无路可走 |
| **D3** | 事故致死 | `Choice.critFail` 写明 `death`（非 major） | ⚠️ 部分（正文必须给出危险信号） | **致死率按危险等级分档**（§4.3），不许一律 5% |
| **D4** | 慢性致死 | 长期 Debuff 未治疗 → 致命属性归零 | ✅ 能（Debuff 可见 + 倒计时） | 必须给至少一条"缓解/治疗"路径 |

### 2.1 硬性约束（引擎需保证）

1. **D2/D3 的致死项必须可规避**：同一条事件里必须存在至少一个**不增加死亡风险**的选项（即 `caps` 门槛规则"做加法不做减法"的同类原则——**不把玩家逼进必死分支**）。
2. **D3 必须在正文里给出危险信号**：出现"边缘""锈蚀的护栏""不许伸手"之类的提示，让玩家在**信息充分**的前提下承担风险。禁止突然致死。
3. **致死率必须写在数据上，不许藏在引擎里**：所有致死概率由事件字段声明，引擎只负责掷。**AI 生成的内容也必须显式声明致死率**，否则审查打回。
4. **D2/D3 一生最多触发一次**（`once` 语义 + 致死事件不重复），避免同一事故反复"抽生死签"。

## 3. D1 衰竭：致命属性白名单（新增）

### 3.1 问题

现在 `checkEnd()` 对**任何**属性 ≤ 0 都判死。实测 120 局里出现"家境=0 穷死""颜值=0 丑死"，与设计意图不符。

### 3.2 规则

`AttrDef` 新增 `fatal?: boolean`。**只有 `fatal: true` 的属性归零才等于死亡**；其余属性归零改为**「困境」**——不结束人生，但立刻施加持续压力。

| 系统 | 致命属性 | 非致命（归零 → 困境） |
|---|---|---|
| `classic5` | `constitution`（体质） | `appearance` 颜值 / `family` 家境 / `happiness` 快乐 / `intelligence` 智力 |
| `heart6` / `roulette` | `vitality`（行力） | `insight` / `resolve` / `empathy` / `ingenuity` / `reverie` |

> `health` 语义键在 `heart6` 下映射到 `vitality`（01 文档已定），所以在六维系统里**只有行力一条生死线**。这是刻意设计——人生只有一条命，不是六条。

### 3.3 困境的效果（归零时立刻结算）

| 归零属性 | 困境 | 效果 |
|---|---|---|
| 家境 / background | 赤贫 | 每年 `mood -1`，无法选择任何 `money` 门槛选项，直到回到 3 以上 |
| 快乐 / mood | 麻木 | `psyche.suppression +2`，且"向人倾诉"类选项全部不可用 |
| 颜值 / appearance | 自弃 | `psyche.selfWorth -2` |
| 智力 / insight / ingenuity | 迟钝 | 所有 `DC.hard` 以上检定 `-2` 修正 |
| 共情 / empathy | 冷硬 | 关系类事件不可用（`relations` 相关 `require` 全部失败） |

> **困境的解除**：回到该属性 ≥ 3 即自动解除。困境期间 UI 必须显著提示。

## 4. 事故的致死档位（新增机制）

### 4.1 新字段

```ts
export interface Choice {
  // ... 现有字段
  /**
   * 「重大变故」：本次选择的风险等级。缺省 = 安全（普通失败只造成重伤）。
   * 仅对 fail 分支生效——大失败（critFail）永远按 §4.3 顶格处理。
   */
  hazard?: HazardLevel;
  /**
   * 仅在写 FAIL 分支时生效：这一档事故的致死概率 0~1。
   * 引擎在 fail 分支结算后按此概率二次判定，命中则当场结束人生。
   * 普通失败**默认不致死**，只有声明了 failLethal 的选项才可能。
   */
  failLethal?: number;
}

/** 事故危险等级：决定致死率区间、重伤程度与是否留下永久创伤 */
export type HazardLevel = 'none' | 'low' | 'mid' | 'high' | 'lethal';
```

### 4.2 危险等级表（**这是本次改动的核心数值**）

| 等级 | 典型情境 | 普通失败（`fail`） | 大失败（`critFail`） |
|---|---|---|---|
| `none` | 日常交涉、读书、买卖 | 仅属性/心理损失 | 数值强化 ×0.5（**不致死**） |
| `low` | 打架挨揍、熬夜硬扛 | −1~−3 属性 | ×0.5 强化 + 永久标签 |
| `mid` | 械斗、黑诊所手术、高危义体接入 | −3~−5 属性 + **永久标签** | **致死 8%** 或永久残疾 |
| `high` | 从高处摔下、被车撞、重度感染 | −4~−6 属性 + **永久标签 + 1 条 Debuff** | **致死 15%** |
| `lethal` | 卷入重工机器、爆炸、致命剂量 | **致死 10%**（`failLethal: 0.10`）+ 重伤 | **致死 35%**（`LETHAL_CAP`，见 §4.3） |

> **用户口径（2026-10-08）**：「按普通失败=重伤、大失败=死的逻辑，但重大变故的概率要调低一点。」
> 因此上表的 8% / 15% / 35% 是**首版提案**，比"大失败必死"温和；实际手感需要按 `_audit/_scratch` 的模拟脚本校准后再定稿（见 §8 验收标准）。

### 4.3 三条硬规则

1. **大失败致死率上限 35%**（常量 `LETHAL_CAP = 0.35`）：即使是 `lethal` 等级，也不允许"大失败必死"（必死会让 slider 式的人生没有喘息空间）。
2. **`failLethal` 只允许写在 `hazard: 'lethal'` 的选项上**，且数值不得超过 `0.10`。其他等级写 `failLethal` 一律审查打回。
3. **`hazard` 必须在正文里留下对应的危险信号**（见 §2.1 第 2 条）。

> **与「成功但有代价」的关系（2026-10-08 补充）**：本节的 `hazard` / `failLethal` 只负责**风险与致死**；
> 「代价」的表达式统一由 **`Outcome.cost`** 承担（见 [10 文档](./10-outcome-and-attribute-rebalance.md) 第 2 节）。
> 两者的分工是：`hazard` 决定**会不会死、有多危险**，`cost` 决定**付了什么价**。写事件时两者可以同时出现。

## 5. 失败的代价（三档齐上）

### 5.1 三档定义

失败不再是"扣几点属性"，而是**三档同时生效**：

| 档 | 名称 | 载体 | 持续时间 | 作用 |
|---|---|---|---|---|
| **一档** | 伤势减益 | **`Debuff`（新增）** | 数年 / 永久 | **持续啃属性**，需要花钱或休养才能好 |
| **二档** | 永久标签 | `tags`（现有） | 永久 | 长出**因果支线**：后续事件可以 `require` 它（"右肩抬不起来"→ 拿不了重物） |
| **三档** | 残疾 / 病理 | `gainTraits` / `gainCaps`（现有） | 永久 | **小概率**（`mid` 以上、`critFail` 为主），改变能力门槛分支的走向 |

> **写法统一说明（2026-10-08）**：这三档在数据里的位置，统一由 **`Outcome.cost`** 承载
> （`success.cost` = 成功但有代价；`fail.cost` = 失败的额外代价，等价于直接写进 `fail.effects`）。
> 完整语义见 [10 文档](./10-outcome-and-attribute-rebalance.md) 第 2 节。本节定义**代价该有多重**，10 文档定义**代价写在哪**。

### 5.2 `Debuff`：新增类型

```ts
export interface Debuff {
  id: string;
  /** 持续年数；与 permanent 二选一 */
  years?: number;
  /** 永久伤势（不可自然痊愈，只能靠特定事件移除） */
  permanent?: boolean;
  /** 生效期内的语义属性年变化（允许小数，走与 TIME_DRIFT 相同的叠加通道） */
  perYear?: Partial<Record<SemanticAttr, number>>;
  /** 生效期内的检定修正（负值） */
  checkPenalty?: number;
  /** 每年扣钱（治疗费 / 药费） */
  costPerYear?: number;
  /** 展示文案（心理状态量面板旁显示，如「肋骨未愈 · 还剩 2 年」） */
  label: string;
  /** 可移除它的方式（供作者与 AI 参考，引擎不强制） */
  cure?: 'rest' | 'money' | 'surgery' | 'none';
}

export interface RunState {
  // ...
  /** 生效中的伤势/病根（2026-10-08 新增） */
  debuffs: Debuff[];
}
```

### 5.3 为什么需要 `Debuff`（而不是只扣属性）

实测：**失败后 3 步内，行力回到失败前水平的有 90%**。
因为"一次性 −5 行力"会被下一个事件发的 +3、再下一个 +2 直接抹平。**`Debuff` 是不一样的东西**：它每一年都在扣，玩家必须**主动处理**（花钱 / 放弃某个机会去休养）才能止血。

### 5.4 写作配额（防止失败被滥用）

| 情境 | 一档 Debuff | 二档 永久标签 | 三档 残疾/病理 |
|---|---|---|---|
| `hazard: none/low` 的日常失败 | 可选 1 条（`years: 1~2`） | 可选 | ❌ 禁止 |
| `hazard: mid` | 建议 1 条（`years: 2~5`） | **建议必有** | 仅 `critFail`，且 ≤ 一条 |
| `hazard: high` | **必有** 1 条（`years: 3~8`） | **必有** | `critFail` 可给 |
| `hazard: lethal` | **必有**（可 `permanent: true`） | **必有** | `critFail` 可给 |

### 5.5 现有的 31 个"失败反而涨属性"怎么办

**不是错误，但需要分类处理**，文档给出判定标准：

| 情形 | 判定 | 处理 |
|---|---|---|
| 失败给了 `mood`/`empathy` 之类的**精神收获**（如"你没做到，但你想通了一件事"） | ✅ **合法**：这是"失败中的成长" | 保留，但**必须**同时有一档或二档代价，否则失败无成本 |
| 失败给的净收益 **≥ +2** 或给了**关键标签** | ❌ **不合法**：失败比成功划算 | 按 §5.4 配额补代价，或把它改成 `success` 分支 |
| 失败什么都没给（0 个） | ⚠️ **可接受但不好** | 至少给二档永久标签或心理代价 |

> 实测当前 31 个净收益为正的失败分支里，`cb_youth_028`（失败给 `empathy+2, mood+1`）属于第二类，需要改。

### 6.1 UI 必须表达的三件事（否则机制白做）

1. **危险标注**：`hazard: 'high' | 'lethal'` 的选项上必须显示风险等级（如 `⚠ 高风险`），让玩家在信息充分下决策；
2. **伤势可见**：`Debuff` 在心理状态量旁边显示 `label` 与剩余年数；
3. **困境提示**：属性归零进入困境时，在属性面板上标红并写出后果。

## 7. AI 生成规则（给 08 文档的第 4 节补充）

> 本节会被直接摘进 `08-ai-text-spec.md`，作为发给 AI 的规则。

给 AI 的三条硬规则：

1. **判断危险等级再写分支**：拿到事件梗概后，先按 §4.2 判定 `hazard`，再决定 `fail` / `critFail` 的严重度。**不许所有事件都用同一档**。
2. **`fail` 不是"什么都没发生"**：必须至少给**一档或二档代价**（Debuff 或永久标签）。写不出代价的，说明这个检定不该存在——改成无检定的叙事选项。
3. **致死必须显式声明且克制**：只有 `hazard: 'lethal'` 才允许 `failLethal`（≤ 0.10）；`critFail` 致死率 ≤ 0.35；**任何致死选项都必须在同事件里留一条安全路径**。

附：AI 输出的事件 JSON 需新增的字段

```jsonc
{
  "choices": [
    {
      "label": "…",
      "check": { "attr": "vitality", "dc": 16 },
      "hazard": "high",            // none | low | mid | high | lethal
      "failLethal": 0.1,           // 仅 lethal 可用，≤ 0.10
      "success": { "effects": {} },
      "fail": {
        "effects": {
          "attr": { "health": -5 },
          "tags": ["摔断过骨头"],
          "debuff": [{ "id": "debuff_broken_ribs", "years": 3, "label": "肋骨未愈", "perYear": { "vitality": -0.3 }, "cure": "rest" }]
        }
      },
      "critFail": { "effects": { "death": "…" } }
    }
  ]
}
```

## 8. 验收标准（**只改代码不跑模拟不算完成**）

沿用 `01` 文档第 6 节的纪律：

1. **致死率校准**：按 `_audit/_scratch/probe*.mjs` 的模拟框架，各 `hazard` 等级各跑 ≥200 局，实测致死率与 §4.2 声明值的偏差 ≤ ±3 个百分点；
2. **寿命影响可控**：补齐事故致死内容后，`probe4.mjs` 的四档寿命中位数**不得下移超过 3 岁**（事故死亡是左尾事件，不该改变主分布）；
3. **失败有代价**：`failcheck.mjs` 的"失败后 3 步内恢复"比例应从当前的 **90% 降到 60% 以下**；
4. **不出现必死分支**：`gating.js` 扩展一条校验——任何事件的任选项组合下，都必须存在至少一条不通向 `death` 的可行路径；
5. **D2/D3 可预见**：所有 `hazard` 非 `none` 的选项，UI 上必须能读出风险等级（渲染断言）。
