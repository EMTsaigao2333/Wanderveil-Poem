# 幻行诗篇 · Wanderveil Poem

> 一段被抽出来的人生。你无法选择自己是谁，只能决定怎么活。

微信小程序 · 类「人生重开模拟器」的**叙事化人生模拟**游戏。
在虚构或真实的世界观里重开一段人生，逐年做抉择、掷骰检定、承担后果，
一生结束后生成**人生总结图**。

原生小程序 + TypeScript，**零运行时依赖**。

## 这是什么

不是「选选项看小说」，也不是「堆数值刷属性」。这个项目的核心主张是：

**把 TRPG 的检定手感，装进「一段人生」的叙事结构里。**

三套属性系统开局可选，同一份事件库都能跑：

| 属性系统 | 内容 | 适合 |
|---|---|---|
| **经典五维** | 颜值 / 智力 / 体质 / 家境 / 快乐（+隐藏幸运） | 第一次接触，直观易懂 |
| **心之禀赋** | 洞见 / 持守 / 通感 / 机变 / 遐思 / 行力（+隐藏命途） | 想要跑团检定手感；外貌家境改为开局背景词条 |
| **全随机（转盘）** | 转盘抽特质 → 特质直接定义六维 | 「把命运交给转盘」 |

事件库只写**语义属性键**（`perception` / `will` / `health` …），
由属性系统的映射表折算到具体数值 —— 所以**一份事件库可以同时支持多套系统**。

## 现在能玩到什么

一个完整可跑通的闭环：

```
开局向导（选世界 → 选属性系统 → 内容偏好 → 转盘抽卡 → 人物卡 → 起名）
      ↓
人生页（逐年事件 → 抉择 → 检定骰子动画 → 结果与变化 → 属性面板）
      ↓
结局（死因 + 最终属性 + 人生时间线倒序）
```

- **开局向导**：六屏流程。内容偏好面板按 9 个类别分组，可整组开关或逐条勾选
  （敏感/轻不适内容**默认全关**，默认体验是「平凡的出生」）
- **转盘抽卡**：主线槽逐个定格（每槽 0.65s，可跳过），副线池按概率翻「命运牌」；
  人物卡上可**改写一次副线**（主线槽是「命」，不可改）
- **检定**：`1d20 + floor(属性/2) ≥ DC`，骰面 20 大成功、骰面 1 大失败；
  有骰子滚动动画，约 0.8s 后揭示真实结果
- **存档**：本地 5 个存档位（硬上限，满了不自动删除，由玩家自己选删哪个）
- **确定性随机**：同种子完全复现，读档续玩与不中断玩的结果一致

## 快速开始

### 环境要求

- [微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)（稳定版）
- Node.js（**仅用于类型检查**，不是运行时依赖）

**不需要 `npm install`。** 这个项目没有 `node_modules`，打开开发者工具就能编译运行。

### 运行

1. 用微信开发者工具「导入项目」，选择**仓库根目录**（不是 `miniprogram/`）
   > ⚠️ 必须选根目录。根目录的 `project.config.json` 里配置了
   > `useCompilerPlugins: ["typescript"]`（没有它 DevTools 不会编译 `.ts` 文件）
2. 填入你自己的小程序 AppID（`project.config.json` 里的 `appid` 换成你的）
3. 编译运行。首页是开局向导。

### 类型检查

```bash
npx tsc --noEmit -p miniprogram/tsconfig.json
# 或
npm run typecheck
```

> `miniprogram-api-typings` 的官方声明是 2.8.x，与较新的 tsc 不兼容，
> 所以 `miniprogram/tsconfig.json` 开了 `skipLibCheck: true`（属第三方声明问题）。

### 校验与平衡模拟（可选，但强烈建议）

引擎是**纯 TypeScript、世界无关**的，不依赖任何小程序 API，可以直接在 Node 里跑
（Node 24 原生剥离类型 + `tools/lib/ts-resolve.mjs` 这个 resolve hook）。
**这个项目的所有数值都是这么测出来的**：

```bash
npm run validate                                            # 数据契约校验（15 项）
npm run simulate                                            # 批量模拟 480 局
node tools/simulate.mjs --runs 96 --strategy life           # 按「活法」策略分五档
node tools/simulate.mjs --runs 100 --system classic5 --strategy first
```

| `simulate.mjs` 参数 | 取值 |
|---|---|
| `--runs` | 局数，默认 480（`--strategy life` 时是**每档**局数，共 5 档） |
| `--system` | `heart6`（默认）/ `classic5` / `roulette` |
| `--strategy` | `random`（默认）/ `first` / `life` |

退出码：`0` = 全部通过，`1` = 有断言未通过。
**断言不允许为了让脚本通过而放宽** —— 当前 `simulate` 会如实报告
「实测寿命中位数 68~70 岁 vs 文档目标 40 岁」这个已知缺陷。

详见 [`tools/README.md`](tools/README.md)。

## 玩法与系统

### 人生模型

不是所有世界都从生到死。每个世界声明自己的模型：

| | `full` 完整一生 | `episodic` 片段连载 |
|---|---|---|
| 起点 | 固定 0 岁 | `startAge` 指定 |
| 推进 | 年龄（`years`，默认 1） | 章节（`chapters`） |
| 时间漂移 | 启用 | 默认关闭（选择驱动） |
| 终局 | 死亡 | 章节完结 / 多结局 |

### 人物构建层

**235 条通用特质 + 世界专属特质**，分 15 个槽位：

- **主线槽（10 个，必抽）**：性别 / 身高 / 体型 / 发色 / 瞳色 / 视力 / 容貌 / 性格 / 道德 / 出身
- **副线池（6 个，按概率抽）**：生理形态 40% / 生理机能 30% / 心理人格 45% /
  心理病理 20% / 天赋才能 35% / 社会细项 30%
  （「抽不中」就是「无」，池内不列 `none` 条目）

特质携带**六维偏移向量**，合成规则 = `基线 + Σ(特质偏移)`，再 clamp。
特质可在人生中被事件改写（获得/失去按增量加减，**但不整体重算** ——
已发生的人生不会被后来的特质改写历史）。

### 心理状态量

不是标签，是**数值**：

```
PsycheState { resilience 韧性 / trust 信任 / selfWorth 自我价值
              suppression 压抑度 / conditions 已触发病理 }
```

压抑度累积过阈值（8 / 14 / 20）触发临床病理，可**分档加重、降档、移除**。

### 检定与后果

- 所有玩家抉择都带检定（当前 161 条事件、314 个选项，**100% 覆盖**）
- **大成功 / 大失败**：顺风的一半 ×1.5、逆风的一半 ×0.5；
  **标签、特质、能力、生死一律不被随机数改写**（那些是作者写死的因果）
- **做加法不做减法**：能力门槛（失明 / 轮椅 / 失聪）只**追加**选项，从不屏蔽选项，
  且引擎硬保证「不存在所有选项都被门槛挡掉的事件」

## 项目结构

```
miniprogram/
├── engine/                 引擎层（世界无关，1839 行）
│   ├── schema.ts             剧情数据结构总定义
│   ├── story-engine.ts       推进循环 / 检定 / 结算 / 死亡叙述
│   ├── roulette.ts           转盘抽卡（确定性 RNG）
│   └── run-state.ts          RunState 运行时 + 存档格式
├── data/                   数据层（4849 行）
│   ├── attributes.ts         三套属性系统 + 语义键映射 + 时间漂移
│   ├── traits/               特质池（通用 235 条 + 赛博朋克专属）
│   └── worlds/
│       ├── _TEMPLATE/        新世界写作模板
│       └── cyberpunk/        世界：赛博朋克 · 雾港（161 条事件）
├── pages/                  页面层（871 行）
│   ├── onboarding/           开局向导（六屏）
│   └── play/                 人生页（逐年事件 + 检定动画 + 结局）
├── utils/                  跨页面共享契约
├── app.json / app.ts / app.wxss
└── tsconfig.json

tools/                      校验与平衡模拟（零依赖，Node 直接跑）
├── lib/load-ts.mjs           TS 加载器（import 即注册 resolve hook）
├── lib/ts-resolve.mjs        ESM resolve hook（补 .ts 扩展名）
├── validate-data.mjs         数据契约校验（15 项）
└── simulate.mjs              批量模拟 + 对照文档目标的断言

docs/design/                设计文档（01~10，2147 行）
typings/                    微信官方类型声明
```

**分层原则**：`pages` → `engine` / `data` / `utils`。
**页面之间禁止互相 import**（`app.json` 开了按需注入 `lazyCodeLoading`，
页面 JS 被其他文件 require 会报 `module not defined`），
共享代码一律放 `engine/` / `data/` / `utils/`。

## 技术选型与关键决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 前端 | **原生小程序 + TypeScript** | Canvas / 插件 / 音频兼容性最好，不引框架 |
| 运行时依赖 | **零** | 无 `node_modules`，打开 DevTools 就能跑；主包仅 456 KB |
| 事件库结构 | **语义键中间层** | 一份事件库同时支持多套属性系统 |
| 检定 | `1d20 + floor(属性/2) ≥ DC` | `floor(/2)` 让「运气跨度 : 能力跨度」保持约 1.9:1，骰子有分量 |
| 随机数 | **确定性**（mulberry32 + `(seed, step, salt)` 重算） | 存档只存种子，读档仍可复现，不必存 RNG 状态 |
| 敏感内容 | **标记 + 默认关闭 + 逐条放行** | 一开局就被抽到残疾或病理会直接毁掉这一局 |
| 立绘形象 | **P0 用文字描述** | 特质携带提示词（`promptTags` / `promptNegative` / `moodTags`），二期接绘图时零成本 |

## 已知问题

> 这些是通过**实跑引擎**（1000+ 局模拟 + 14878 次真实检定）测出来的，不是猜测。
> 数值类问题需要先定几个口径才能改（见「路线图」）。

### 已修复

| | 问题 | 修复结果 |
|---|---|---|
| ✅ | **死因文案坍缩** | 属性耗尽时使用的死因 key 永远是 `default` → 120 局里 **116 局**显示同一句话。现改为按属性分池，实测死因已变成具体文案（如「你的行力在下雨的早晨用完了。」） |
| ✅ | **「任何属性归零即死」** | 曾出现「家境=0 穷死」「颜值=0 丑死」。现改为致命属性白名单（`AttrDef.fatal`），六维只有**行力**一条生死线 |
| ✅ | **存档版本不匹配即丢弃** | 曾直接 `return null` 并被界面显示成「上一局已经结束了」。现改为逐级迁移 + 拒绝前备份 |
| ✅ | **重大变故致死率扁平** | 5 处致死全挂在 `critFail` 上、统一 5%。现引入 `hazard` 五档危险等级 + `failLethal`（普通失败也可致死） |
| ✅ | **失败无代价** | 失败后 3 步内属性恢复比例 **90%**。现引入伤势 `Debuff`（每年持续扣属性）+ `Outcome.cost`（成功但有代价） |
| ✅ | **骰子动画竞态** | 动画期间点「继续」会把上一条结果盖到新事件上。已加守卫 + 定时器归属校验 |
| ✅ | **随机数隐式契约** | `rngFor` 曾用 `history.length` 当随机坐标。现改为显式 `RunState.step` |
| ✅ | **`worldId` 未贯通** | 世界选择曾是装饰性的。现已贯通到页面层 |

### 待处理（需要先定数值口径）

| 严重度 | 问题 | 实测 |
|---|---|---|
| 🔴 | **寿命四档失效** | 文档目标 40 / 55 / 60 / 65+，实测五种「活法」策略的**中位数全是 68~70 岁**，偏差 **+28 岁** |
| 🔴 | **属性饱和** | 六维饱和度中位 **98%**，p90 = 100%，**57.5%** 的检定发生在属性已贴顶时 → 17 岁后属性不再成长，「成长感为零」 |
| 🔴 | **难度失真** | DC 16 实测成功率 **66%**（文档预期 35%）；文档按「属性 10」写预期，实测检定属性中位是 **16** |
| 🟠 | **大成功收益被吃掉** | **45.9%** 的检定属性剩余空间 ≤ 2，大成功的 ×1.5 被上限直接抹平 |
| 🟠 | **病理链空转** | 压抑度终局中位 **4**，阈值是 8 → **84%** 的局病理从未触发 |
| 🟠 | **经济失衡** | **60%** 的局出现负资产，最低 −357,260；`Condition` 缺金钱门槛，买不起照样扣款 |
| 🟡 | **`years` 字段零使用** | 161 条事件里一次都没用 → 每条事件严格消耗 1 年，跨年叙事无处表达 |

**修复方向**已在 [`docs/design/09`](docs/design/09-fatality-and-consequence.md) 与
[`docs/design/10`](docs/design/10-outcome-and-attribute-rebalance.md) 定义。

你可以自己复现这些数字：

```bash
npm run simulate          # 退出码 1，会打印「实测 68 vs 目标 40」的对照
npm run validate          # 退出码 0，数据层是干净的
```

## 路线图

1. **数值定稿** —— 属性去饱和、DC 重解、寿命重校准、金钱尺度统一
2. **机制补齐** —— 致死档位、失败代价、后效队列（「15 年前那个决定」的回收）
3. **多世界通路** —— `worldId` 贯通 + 漂移曲线外置到 `WorldMeta`
4. **人生总结图** —— 维度无关雷达图 + 事件时间线 + 人物卡特质可视化
5. **第二个世界** —— 现代美国底层（与现有世界共享全部语义与时间模型，改造成本最低）
6. 美术风格系统（构成主义 / 纸艺拼贴 / 达达主义）+ 正式首页视觉
7. 二期：作者付费内容、玩家 UGC、AI 线路生成、TTS + 语音识别
